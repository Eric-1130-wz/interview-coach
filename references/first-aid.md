# 面试前急救包（临门 30~60 分钟）

触发词："明天就面""还有一小时/半小时就面""临时抱佛脚""急救""马上要面了"。此模式不演完整面试官——来不及了，做减法。

## 模式说明（开场向用户讲清）

- 教练清单模式，20–40 分钟，只过 4 件事，不多练。
- 明确告知："这是急救不是系统训练，面试结束后回来做一次完整复盘再补课。"
- 用户极度紧张时先说一句：急救包的目标不是变强，是让你明天不出昏招。

## 急救四件事（按顺序，每件限时）

### 1. 三个项目故事压到 60 秒（10 分钟）
让用户口述最熟的三个项目/经历 → 按每个 60 秒砍：背景一句、我的动作两句（含一个数字）、结果一句 → 现场让用户重说一遍计时，超时继续砍。三个故事覆盖：最能打的、最体现团队协作的、一次翻车后补救的。

### 2. 自我介绍 90 秒版（5 分钟）
只保四要素：是谁（学校专业一句话）、最相关的经历一句（对准 JD 关键词）、一个可验证的成果数字、为什么来一句。让用户口头过两遍。

### 3. 高频五问速记（15 分钟，每问给 3 点框架，不写完整答案）
1. 为什么选我们/这个岗位？→ 行业一句 + 岗位一句 + 自己一句（兴趣或经历钩子）
2. 三个优缺点？→ 真实 + 不致命 + 各配一句"我怎么管它"；缺点远离岗位红线（财务别说粗心）
3. 最大的挫折/失败？→ 事情一句 + 责任界定干净 + 学到什么 + 后来怎么改的
4. 未来 3 年规划？→ 立足岗位谈成长，不谈跳槽不谈考研考公
5. 反问问什么？→ 备两个：新人培养/团队现状（薪资加班千万别问第一句）
每问让用户用 30 秒口头过一遍框架，卡住就再过一遍。

### 4. 红线三强调（3 分钟）
从用户场景对应的场景文件"常见扣分点清单"里**只抽 3 条最致命的**当面提醒（如技术岗=数字口径、结构化=超时、群面=抢话、国企=问轻松吗）。

## 收尾（2 分钟）

- 心态一句话："明天只需要不出昏招 + 三个故事讲清楚，就赢了大多数人。"
- 若场景允许且有时间富余，可加一轮"只问一道你简历里最虚的问题"的快问快答。
- **产出物（必做，双形态——急救卡的价值在"候场随手能看"，只落成工作区文件等于把它锁起来）**：
  1. **对话内纯文本急救卡（首选）**：直接在聊天里输出一屏纯文本——无表格、无 Markdown 符号、每节 ≤5 行、节间空行分隔——并提示用户"全选复制到手机备忘录；明天候场时你手里只有手机，打不开电脑里的文件"。内容：三个 60 秒故事压缩版（每段含数字）、90 秒自我介绍文字版、五问三要点框架、三条红线、明日面试时间地点核对行。用词极简，因为它是给高度紧张状态的人看的。
  2. **《面试急救卡-YYYYMMDD.md》写入工作区存档**（同内容，用于事后复盘对照与手机丢失时找回），生成后明示"存档已落盘，手机里那份才是明天用的"。
- 落日志（无评分场次）：mode 填"急救包"、scenario 记"急救包：目标岗位+时间"，**不填六维分、total、passed**（急救包不做评分复盘也无资格判定过关——脚本存 null，不会打断已攻克状态、不污染弱项序列）；weak_point 记明天面试将面对的最大风险（仅作登记），next_retest 记"面试后回来完整复盘"。

## 边界

- 急救包不做完整模拟、不出整套题、不做评分复盘（时间不够，做了反而不熟）。
- 用户只剩 10 分钟以下：只做第 1、4 件事。
