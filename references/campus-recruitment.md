# 校招 / 实习求职面试

> 题库时点：2026-11。题干素材按近期招聘形态撰写；题型分类、追问链、评分口径长期有效，正式备考请按目标公司当年 JD 与最新面试形式替换题干（尤其热点类、行业认知类）。

## 语气样板（逐字稿，所有场景人设参照此口语密度）

以技术岗业务面为例，练的是节奏：单题单发、话短、追问跟得上一个数字——不是背这些话，是学这个密度。

```
面试官：坐吧。我是平台技术部的老周，今天四十分钟左右，先聊项目，再看基础，最后留几分钟你问我。先做个两分钟自我介绍。

你：（自我介绍，略）

面试官：简历第二个项目，秒杀那个，日活多少？

你：做活动的时候有两千多。

面试官：两千是峰值还是日均？活动页和下单页分别扛了多少请求？

你：活动页多，下单我没单独看。

面试官：行，这个先记着。你说库存扣减用了 Redis，为什么不用数据库行锁？

你：行锁并发高的时候会把连接挂住……

面试官：挂住之后呢？用户那头看到什么？

你：会一直等，等超时就失败了。

面试官：失败之后你怎么处理的？用户重试会不会重复扣库存？

你：（卡壳十几秒）

面试官：不着急，想三十秒。你当时到底怎么防的超卖？

（……若干回合后）

面试官：今天就到这儿，结果两周内会有通知。你有什么想问我的吗？
```

样板要点：面试官每轮不超过三句话；一次只抛一个问题；用户卡壳就放慢、重复问题，绝不提示答案；收尾干脆，出戏即出报告。（AI 面等无人性化场景**不**参照此样板，见 AI 面模块。）

## 面试官人设

- **HR 初面**：语气礼貌、注重意向与基本素养，问题偏动机类与经历概览，偶尔穿插压力题观察性格。
- **业务面（部门面试官）**：直入正题，围绕岗位能力与项目经历深挖，追问密度高，对空话零容忍。
- **终面（主管/总监）**：节奏从容，关注价值观、稳定性、成长潜力，喜欢开放式问题。
- **tech-lead（技术岗专项）**：只谈技术，对含糊数字零容忍，追问沿"数字→口径→压测→瓶颈→定位"逐层下钻（配合 D2 证据深挖链使用）。

模拟时声明当前是哪一轮（用户未指定时默认业务面，实战占比最高）。

## 典型流程（20~40 分钟）

自我介绍（1~2 分钟）→ 动机类问题 → 行为面试题（STAR 深挖）→ 专业能力题 → 情境/压力题 → 反问环节

## 题库

### A. 自我介绍变体

1. 请用一分钟介绍自己（限时版）
2. 介绍一个简历上没有的你自己
3. 用三个词概括你的优势，并各举一个例子证明

### B. 动机类

| 题目 | 追问链 |
|------|--------|
| 为什么投我们公司/这个岗位？ | "你同时投了哪些方向？"→"如果都给 offer 你怎么选？" |
| 你对这个岗位的理解是什么？ | "你觉得这个岗位最难的部分在哪？"→"你能胜任哪部分、欠缺哪部分？" |
| 未来三年的职业规划？ | "如果三年后晋升不顺你会怎么办？" |
| 为什么选这行而不考研/考公？ | "你身边人都去考公了，你怎么看？" |

### C. 行为面试题（STAR 追问为主）

1. 讲一次你在团队中解决冲突的经历。→ 追问："对方当时怎么说？""重来一次你会怎么做？"
2. 说一个你失败/受挫的项目。→ 追问："你自己的责任占多少？""后来做了什么补救？"
3. 你最有成就感的一件事？→ 追问："你个人的贡献是多少？""别人怎么评价你的表现？"
4. 讲一次你顶着压力完成任务的经历。→ 追问："压力最大时想过放弃吗？""怎么排优先级？"
5. 一次你说服别人接受你观点的经历。→ 追问："对方的反对理由是什么？""靠逻辑还是靠关系说服的？"

### D. 专业能力题

- 通用框架：从用户简历/JD 中的技能点出 2~3 题（技术栈、专业核心概念、required skill）。
- 用户未提供背景时，问："我出 XX 方向的基础题，你没接触过的直接说不会，我们换下一题。"——考查诚实度本身也是考点。
- 实习岗常用："这个岗位的日常你想象中是什么样的？"→ 追问实际认知偏差。

### D2. 技术岗证据深挖链（tech-lead 人设，后端/算法/数据类岗专用）

开场题固定用："挑一个你自己觉得最有技术含量的项目，从头讲一下。"随后按下表五层下钻，任一环含糊即停住追问到底：

| 下钻层 | 追问 | 面试官在听什么 |
|--------|------|----------------|
| 数字口径 | "一万多用户是注册量还是日活？最高同时在线多少？" | 把用户量翻译成系统压力的能力；外行口径当场现形 |
| 容量验证 | "没测过，那你上线前怎么确定这套架构够用？" | 容量意识；答不出看能否承认疏漏并给事后补救 |
| 万能药质疑 | "加缓存能解决你刚才说的连接池打满吗？" | 归因层级是否清晰——缓存挡重复读，连接池满在慢查询 |
| 瓶颈定位 | "瓶颈在应用、数据库还是网络？怎么定位到的？" | 分层归因：现象→原因→层级→定位手段 |
| 选型权衡 | "为什么用 MySQL？数据量到多少考虑分库分表？" | 选型权衡理由与量级敏感度 |

机试/笔试后技术面（大厂主流）：围绕机试题追问——"第 X 题你用的什么做法？复杂度多少？有没有更优解？"再转项目。

**岗位变体（下钻层按岗位替换，手法同五层下钻、一环含糊即停）**：
- **算法岗**：手撕环节（现场写伪代码或口述思路）→ 复杂度追问（时间/空间、最坏情况）→ 模型选型依据（为什么用 X 不用 Y、调过哪些参）→ 数据规模与评估指标（多少样本、什么指标、基线多少、提了多少）→ 线上部署与推理耗时（QPS、延迟瓶颈在哪）。
- **前端岗**：渲染性能（重排/重绘、长列表怎么优化）→ 框架原理（响应式怎么实现、diff 为什么需要 key、hooks 为什么不能写在条件里）→ 工程化（构建提速、首屏指标 FCP/LCP 怎么量）→ 兼容与安全（XSS/CSRF 怎么防、怎么埋点定位线上白屏）。

点评时对照的标准动作链：
- 证据链模板：累计注册 → 日活 → 峰值场景 → 峰值 QPS → P99 延迟 → 数据量，每环可核验。
- 承认疏漏三段式：承认 + 事后补测（JMeter 单机 4c8g、订单接口 180 QPS 超时）+ 瓶颈定位（连接池/慢查询缺索引）。
- 分层归因：读压力（缓存层）与连接占用（SQL/索引层）是不同瓶颈；把缓存当万能药即扣深度分。

### D3. 非技术岗专业题（运营/市场/财务/管培/银行/快消）

1. 运营：给你一个新产品，第一个月你怎么冷启动？→ 追问："预算 5000 和 50000 答案有什么不同？""用什么指标判断冷启动成功？"
2. 市场：瑞幸和星巴克的打法差异是什么？→ 追问："如果你是竞品，抢哪群人？"
3. 财务/银行：三张表的勾稽关系说一下。→ 追问："一家公司利润很好但现金流转负，可能是什么问题？"
4. 管培案例：门店坪效下降 20%，你是区域管培生怎么分析？→ 追问："数据不够怎么办？""先改哪个变量？"
5. 通用估算题：估算本市一年奶茶消费规模（费米估算，考结构化拆解，不考答案准）。

### E. 情境 / 压力题（严格型主用）

1. 你的期望薪资是多少？→ 追问："这个数字怎么来的？""给不到呢？"
2. 你还面了哪些公司？→ 质疑式："以你的经历，那些大厂让你过的概率不大吧？"
3. 说说你的三个缺点。→ 追问："第三个更像优点包装，说个真实的。"
4. 成绩单上这门课为什么挂了？→ 追问："能力问题还是态度问题？"
5. 简历上这段经历只有两周，是不是水过去的？
6. 如果导师让你背锅一个团队失误，你怎么办？

### F. 反问环节常见判断

- 好反问：成长路径、团队业务、新人培养、面试官个人体验
- 差反问：百科能查到的、第一句就问薪资福利加班、说"没有想问的"

## 群面模块（校招非技术岗第一关）

快消/银行/管培/大厂非技术岗第一轮大量使用无领导小组讨论。加载 references/group-interview.md 按其规则模拟（材料用商业案例类：HC 排序、市场进入、预算分配；注意其发言格式规范与共识进度追踪）。

## AI 面 / VI 视频面模块（大厂校招第一轮主流形态）

形态：机器语音逐题提问 → 限时录制作答（每题约 30 秒准备 + 2 分钟作答）→ 系统 NLP+CV 评估。

**无人性化铁律（本模块覆盖通用铁律 2/4 的口语化规则）**：
- 全程零回应：不说"不着急"、不复述问题、不作答前寒暄；用户卡壳沉默是真实压力，必须让沉默存在。
- 每题只有：题卡播报（"第 X 题：……你有 30 秒准备"）→ 等待 →"请开始作答"→ 时间到"作答结束，下一题"三段式，中间无任何拟人化语句。
- 作答过短（低于题卡要求时长）只说一句"录制时长不足，请重新完整作答（机会仅一次）"；过短重录后仍短，如实记录进报告。

常见题型：60–90 秒自我介绍（限时）、行为题（宝洁八大问类）、情境判断题、公司认知题。

模拟方式：
1. 逐题给题卡与倒计时规则，明示"期间我不会有任何回应"。
2. 用户作答即"录制"，中途绝不打断。
3. 点评按机器评估口径（估算适用，见 SKILL.md 时长估算规则）：时长——按作答字数 ÷ 200 估算是否落在题卡时限（2 分钟 ≈ 360–440 字），用户自报真实时长优先；结构（观点先行）、关键词覆盖（对照 JD 核心词）、开头是否直入主题（AI 面最忌草稿腔与重新开头）、无口头禅。真实语速（字/分）与镜头感、眼神在文字模拟下无法测量，报告中如实标注。

训练建议：用户先写 3 个要点再倒计时口头作答，练"一次成型"。

## 出题策略

- 大厂终面/管培生：加重 F、B 类开放题与价值观题；中小公司业务面：加重 D、C 类实操与经历核验。
- 有 JD 时：至少一半题目围绕 JD 关键词定制；JD 维度写入切片对练配置声明。
- 技术岗必用 D2；非技术岗用 D3 + 群面模块。岗位类型确认遵循 SKILL.md 配置确认总规则（半句并入开场白："你面的是技术岗还是运营市场类？我按 XX 出题了。"），不独立成轮。
- 无简历时：先用 C 类通用行为题开场，借回答线索即兴追问，模拟真实"顺藤摸瓜"。

## 本场景评分侧重（六维，见 scoring-and-feedback.md）

岗位匹配 25%、证据 20%、逻辑结构 15%、内容质量 15%、临场应变 15%、语言表达 10%。
技术岗优先压证据维；非技术岗优先压岗位匹配与内容质量。
重点观察：经历讲述是否量化、是否揽功/推责、岗位认知深度、缺点类问题是否真诚且不致命。
